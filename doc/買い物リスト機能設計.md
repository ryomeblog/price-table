# 買い物リスト機能 設計書

## 1. 機能サマリー

底値表に登録された商品の中から「買い物」を ToDo リストのように追加し、買ったらチェックでマークする機能。リストはグループ単位で複数作成・保持できる。

- 底値表画面 ⇄ 買い物リスト画面 をヘッダーのトグルボタンで切り替え
- リスト作成・編集時は **底値表ビュー(チェックボックス付き)** から商品をピック
- 買い物リスト画面は **入れ子アコーディオン**:
  - 外側 = リスト（グループ）。左端チェック → モーダル確認 → リスト物理削除
  - 内側 = 商品アイテム。チェック → グレーアウト + 一番下に移動（物理削除しない、確認不要）。チェックを外せば未チェック群の末尾に戻る
- 商品アコーディオンを展開すると底値表と同じ価格テーブルを確認できる（編集ボタンは非表示）

```
│  ヘッダー: [リスト ⇄ 底値表] トグル / +新規追加 / I/O / クリア │
└────────────────────────────────────────────────────────────┘
       │                                       │
       ├── view='priceTable' (既存)            └── view='shoppingList'
       │       └─ ProductAccordion 一覧                │
       │                                               ├─ ShoppingListIndex (買い物リスト画面)
       │                                               │      └─ リストごとに入れ子アコーディオン
       │                                               │         (リスト ⊃ 商品 ⊃ 価格テーブル)
       │                                               │
       │                                               └─ ShoppingListForm (追加・編集画面)
       │                                                      └─ ProductAccordion + 左にチェックボックス
       │                                                         (底値表ビューを再利用、選択モード)
       │
       └─ 底値表画面では商品追加・編集・価格情報追加(既存)
```

### 遷移ルール

- ヘッダーのトグルボタンは現在の view に応じてラベル／アイコンを切替
  - `view='priceTable'`   → 「📝 買い物リスト」ボタンを表示
  - `view='shoppingList'` → 「🏷️ 底値表」ボタンを表示
- 買い物リスト画面のサブ状態 `subView` は `index | form` の 2 つのみ
  - 商品詳細は買い物リスト画面 (index) 内の入れ子アコーディオンで完結する
- どこからでもヘッダートグルで底値表へ戻れる

## 3. 画面仕様

### 3.1 買い物リスト画面 (ShoppingListIndex) — 入れ子アコーディオン

各買い物リスト（グループ）をアコーディオンで表示。展開すると内部に商品アイテム一覧。

```
┌─────────────────────────────────────────────────────────────────┐
│ [☐] 📝 今週末の買い物    (3件)            ▼            [編集]   │ ← 外側アコーディオン
├─────────────────────────────────────────────────────────────────┤
│   メモ: 週末のまとめ買い  /  作成: 2026/05/10  更新: 2026/05/12   │
│                                                                 │
│   [☐] 牛乳 1L      (5件の価格情報)    最安値: 0.198/ml    ▶    │ ← 内側 (未チェック)
│   [☐] 食パン       (2件の価格情報)    最安値: 1.5/個      ▶    │
│   ─────────────────────────────────────────────────────────    │
│   [☑] ~~卵 Lサイズ~~ (4件)  最安値: 25.8/個               ▶    │ ← 内側 (チェック済 / グレー)
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ [☐] 📝 平日の買い足し    (5件 / 買済 2)   ▶          [編集]    │ ← 折り畳み中
└─────────────────────────────────────────────────────────────────┘

[+ 新しい買い物リストを作成]
```

#### 外側アコーディオン (リスト = グループ)
- **左端チェックボックス**: ON → 親に `onRequestDeleteList(list)` を通知 → モーダル確認 → リスト物理削除
  - 視覚的には常に未チェック表示（即座にモーダルへ）
- **中央領域**: クリックで展開／折りたたみ
  - リスト名、件数バッジ「N件」（買済件数がある時は「N件 (買済 M)」と併記）
  - 展開アイコン
- **右端「編集」ボタン**: `ShoppingListForm` へ遷移
- 展開時はヘッダー背景が `bg-indigo-600` (白文字)、折り畳み時は `bg-gray-100`

#### 内側 (商品アイテム)
- `ProductAccordion` を `showCheckbox` + `readOnly` モードで利用
- 並び順:
  1. **未チェック** (`createdAt` 昇順)
  2. **チェック済み** (`createdAt` 昇順 / グレーアウト + 取り消し線 + `opacity-60`)
- 左端チェック切替:
  - ON / OFF どちらも親に `onToggleItem(itemId)` を通知 → `toggleItemChecked` 実行
  - 確認なし、物理削除なし
  - チェック直後にレンダリングで並び順が更新される
- 商品アコーディオンの展開で、底値表と同じ価格テーブルを表示（編集ボタンは非表示）

#### 空状態
- リストゼロ件: 「最初の買い物リストを作成しましょう」+ 新規リスト CTA
- リスト内アイテムゼロ件: 「このリストには商品がありません。「編集」から商品を追加してください。」

## 4. データモデル

既存の Product / PriceRecord に手を加えず、新エンティティを 2 つ追加。

### 4.1 ShoppingList（買い物リスト = グループ）

```ts
interface ShoppingList {
  id: string;             // UUID
  name: string;           // リスト名 (例: "今週末の買い物")
  description?: string;   // 任意
  createdAt: Date;
  updatedAt: Date;
}
```

**制約**: `name` 必須・1〜50 文字 / `description` 任意・最大 200 文字

### 4.2 ShoppingListItem（リスト内アイテム）

```ts
interface ShoppingListItem {
  id: string;             // UUID
  listId: string;         // ShoppingList.id (外部キー)
  productId: string;      // Product.id (外部キー)
  checked: boolean;       // 「買った」マーク (デフォルト false)
  createdAt: Date;
}
```

設計判断:

- **数量・メモはあえて持たない**（MVP）。商品ピックがメインで、買い物時は底値表側の価格・単価を参照すればよい。将来 `qty?: number; note?: string` で拡張可能。
- 「買った」操作は `checked: true` への更新で表現し、**物理削除しない**。並び順で末尾に下げてグレーアウト表示する。再度チェックを外すと未チェック群の末尾に戻る（撤回可能）。
- 同一リスト内での重複追加は禁止。`(listId, productId)` の組で一意。フォーム側でチェックボックスの状態として表現するため自然と弾ける。

### 4.3 削除カスケード仕様

| 元の操作 | 連鎖処理 |
|---|---|
| `ShoppingList` 削除       | 紐づく `ShoppingListItem` を全削除（モーダルで確認） |
| `Product` 削除 (既存機能) | 該当 productId を持つ `ShoppingListItem` も全削除 |
| `ShoppingListItem` のチェック切替 | 削除ではなく `checked` の更新のみ |

`App.js` の `handleDeleteProduct` は `deletePriceRecordsByProduct` の後に `deleteShoppingListItemsByProduct` を呼ぶ。

### 4.4 ストレージキー

`src/utils/storage.js`:

```js
export const STORAGE_KEYS = {
  PRODUCTS: 'price-table-products',
  PRICE_RECORDS: 'price-table-price-records',
  SHOPPING_LISTS: 'price-table-shopping-lists',           // v1.1.0 追加
  SHOPPING_LIST_ITEMS: 'price-table-shopping-list-items', // v1.1.0 追加
  APP_SETTINGS: 'price-table-settings',
};
```

- `export()` / `import()` の対象に上記 2 キーを追加し、`mergeById` で同方式マージ
- スキーマバージョンは `version: '1.1.0'`
- 古いバックアップ (1.0.0) は当該キーが無い場合に `[]` として読み込む
- 古い形式の `ShoppingListItem` に `checked` が無い場合でも falsy 評価で「未チェック」扱いになり、後方互換性あり

### 4.5 ファクトリ関数

```js
export const createShoppingList = (name, description = '') => {
  const now = new Date();
  return {
    id: generateId(),
    name: name.trim(),
    description: (description || '').trim(),
    createdAt: now,
    updatedAt: now,
  };
};

export const createShoppingListItem = (listId, productId) => ({
  id: generateId(),
  listId,
  productId,
  checked: false,
  createdAt: new Date(),
});
```

## 5. 状態管理（カスタムフック）

`src/hooks/useShoppingLists.js` — `useProducts` / `usePriceRecords` と同じパターン、ただし **`useRef` で最新値を同期保持**してクロージャ問題を回避。

```js
export const useShoppingLists = () => {
  // state + ref (最新値の同期保持)
  // listsRef, itemsRef を commitLists / commitItems で同時更新

  // List 操作
  addShoppingList(name, description?)        // ShoppingList を返す
  updateShoppingList(id, updates)
  deleteShoppingList(id)                     // items もカスケード削除

  // Item 操作
  addItemToList(listId, productId)           // 重複なら no-op
  toggleItemChecked(itemId)                  // checked をトグル (物理削除しない)
  removeItemFromList(itemId)                 // 物理削除 (API としては残置、通常運用では未使用)
  setListItems(listId, productIdArray)       // フォーム保存用: 差分を計算して add/remove
  deleteShoppingListItemsByProduct(productId)// Product 削除カスケード用

  // 取得系 (useMemo)
  getItemsByList(listId): ShoppingListItem[]
  getProductIdsByList(listId): string[]
  getListSummary(listId): { total: number }  // 件数バッジ用
};
```

### 重要な実装上の注意 — クロージャ問題と useRef

`addShoppingList → setListItems → updateShoppingList(updatedAt 更新)` のように、1 イベント内で複数の async ミューテーションを連鎖呼び出しするケースがある。
React の state は次のレンダーまで関数内のクロージャからは古い値しか見えないため、**そのまま `shoppingLists.map()` で書き戻すと直前の追加が消える**。

対策として、`useShoppingLists` 内部で `listsRef` / `itemsRef` を維持し、ミューテーションは ref から最新値を読み、`commitLists(next)` / `commitItems(next)` で ref と state を同時に更新する。

### 6.2 Header.js（改修）

`view` と `onToggleView` を props で受ける。

```jsx
<Header
  view={view}                         // 'priceTable' | 'shoppingList'
  onToggleView={() => setView(...)}
  onAddProduct={...}
  onExportData={...} onImportData={...} onClearData={...}

```

- `view==='priceTable'`   のとき: 「買い物リスト」ボタン (FiShoppingCart)
- `view==='shoppingList'` のとき: 「底値表」ボタン (FiTag)
- 「新規追加」ボタンの意味も view に応じて切替:
  - priceTable   → 商品追加モーダル
  - shoppingList → 買い物リスト追加フォームへ遷移

### 6.3 ProductAccordion.js（改修）

各モード props（既存呼び出しを壊さないよう全て optional + default false）:

```js
<ProductAccordion
  product={...}
  priceRecords={...}
  // 既存 (通常モード)
  onEditProduct, onDeleteProduct, onEditPriceRecord,
  onDeletePriceRecord, onAddPriceRecord
  // モード切替
  readOnly={false}              // 編集/削除ボタンを隠す
  selectable={false}            // 左端にチェックボックス (フォーム選択用)
  selected={false}              // selectable 時の選択状態
  onSelectChange={(productId, checked) => ...}
  showCheckbox={false}          // 左端にチェックボックス (買い物リスト用)
  checked={false}               // showCheckbox 時のチェック状態
  onCheck={(itemId, product, newChecked) => ...}  // ON/OFF 両方で呼ばれる
  itemId={...}                  // 買い物リスト画面で必要
/>
```

ポイント:

- `selectable` と `showCheckbox` は表示形態を分けるため別フラグ:
  - `selectable`  : フォーム用。クリックでトグルし `selected` を反映
  - `showCheckbox`: **買い物リスト用**。`checked` で状態表現。ON/OFF どちらも `onCheck` を呼ぶ
  - `readOnly`   : 編集・削除・価格追加ボタンを描画しない
- `showCheckbox && checked === true` のとき:
  - ヘッダー背景を `bg-gray-300` (グレーアウト)
  - 商品名に取り消し線 (`line-through`)
  - アコーディオン全体に `opacity-60`
- ヘッダー左端に `<input type="checkbox">` を差し込み、本体の展開／折り畳みはチェック操作と独立 (`onClick={e=>e.stopPropagation()}`)

```js
const [expandedListIds, setExpandedListIds] = useState(new Set());
```

```js
const getOrderedItems = (listId) => {
  const listItems = items.filter((i) => i.listId === listId);
  const unchecked = listItems.filter((i) => !i.checked)
    .sort((a, b) => new Date(a.createdAt) - new Date(b.createdAt));
  const checked = listItems.filter((i) => i.checked)
    .sort((a, b) => new Date(a.createdAt) - new Date(b.createdAt));

};
```

## 9. 設計判断と注意点

1. **チェック=並び替え + グレーアウト**: 「買った」は物理削除ではなく `checked` フラグ更新。誤操作で削除して取り戻せない事故を防ぎつつ、UI 上は「下に下がってグレーアウト」されることで進捗を可視化。チェックを外すと未チェック群の末尾に戻り、撤回可能。
2. **リスト削除はモーダル確認**: 外側アコーディオンの左端チェックは「即座にモーダルを開くトリガ」。視覚的には常に未チェック表示で、ON にしても永続的に状態を持たない。
3. **画面遷移**: React Router 7 は依存にあるが現状未使用。新機能のためだけにルーティングを導入するとヘッダー状態管理が複雑化するため、**state ベースの view 切替**で十分。
4. **ProductAccordion の再利用**: モード切替 props 追加で 1 コンポーネントを 3 用途（底値表 / ピッカー / 買い物リスト商品行）に使う方針。各モードは props 分岐のみで完結。
5. **データ整合性**: ① 商品削除時にリストアイテムもカスケード削除、② インポート時はリスト／アイテムも `mergeById`、③ アイテム保存は **差分計算でアトミック反映**。
6. **クロージャ問題対策**: フック内部で `useRef` を導入し、複数の連鎖 async ミューテーションでも最新の配列を参照できるようにする。
7. **重複追加防止**: `setListItems` で `Set` 経由で正規化されるため、フォーム UI 上でも自然と一意になる。
8. **後方互換**: 既存ユーザーの LocalStorage には新キーが存在しない → load 時 `[]` を返すので問題なし。エクスポート JSON のバージョンを `1.1.0` に上げ、`storage.js` で旧版インポート時は空配列を補完。古い `ShoppingListItem` に `checked` が無くても falsy で未チェック扱い。
